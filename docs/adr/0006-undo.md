# ADR-0006 — Undo: snapshot history over copy-on-write documents

Status: Accepted (2026-10-13)

## Decision

* `History` stores the whole `Document` after each action. Documents are trees of `Arc`-shared
  layers whose rasters are copy-on-write `TiledImage`s, so an entry costs only what the action
  changed (a parameter edit: the path of nodes to the layer; a stroke: the tiles it touched).
* Continuous edits (slider drags) coalesce through a merge key until `seal()`.
* **Strokes**: `Stroke::begin` takes O(1) snapshots of the target images; during the stroke the
  live document is edited in place (copy-on-write, so earlier history entries are never touched)
  and every write is recomputed from the pre-stroke snapshot; at stroke end the caller pushes
  the post-stroke document as one entry. Undo/redo restore documents exactly (value equality of
  `TiledImage`s; tested), and pre-stroke tiles are provably untouched (dense comparison).
* **Composite after undo**: `CompositeCache` diffs by pointer identity, so jumping to any entry
  re-evaluates only the tiles that differ, and because tile evaluation is deterministic the
  result is bit-identical to the composite originally computed for that entry (tested).
* Resources are immutable and never removed during a session (any history entry may reference
  them); unreferenced resources are dropped on save.

## Consequences

* No inverse operations to maintain and no separate tile-delta journal; memory is bounded by
  `max_entries` (default 200) and by sharing.
* Anything outside `Document` (camera, selection, tool settings) is deliberately not undoable.
